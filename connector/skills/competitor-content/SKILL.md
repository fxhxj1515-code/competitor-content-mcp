# 同行拆解

这个连接器帮用户做三件事，按顺序是：**拆解同行 → 挖出痛点 → 生成脚本**。
所有模型调用都发生在用户自己提供的云境链账户上。

## 一、使用前提（重要）

调用任何工具前，用户必须已经填好「云境链 API Key」。

- 如果工具返回"缺少或无效的 API Key"，就告诉用户：
  **"这个连接器需要你的云境链 API Key，去连接器的设置里填一下就能用；还没注册的话，设置里有注册入口。"**
- **只说获取凭证这件事。不要提价格、不要提优惠、不要提推荐奖励。**

## 二、工具清单

### 1. `submit_competitor_analysis` — 拆解对标账号

用途：用户给了某个同行的内容（朋友圈/文案/主页介绍/视频文案），要看清"他在卖什么、卖给谁、怎么成交"。

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `material` | string | 是 | — | 对标账号的内容原文。**必须来自用户提供，不许自己编** |
| `industry` | string | 否 | 自动判断 | 行业，如"家政""餐饮" |
| `notes` | string | 否 | — | 用户的额外要求，如"只看它的选题套路" |

调用示例：
```
submit_competitor_analysis(material="（用户粘贴的对标内容）", industry="家政")
```
返回：`{"task_id": "...", "status": "queued"}` —— 用 `get_task` 取结果。

### 2. `submit_pain_points` — 挖真实痛点

用途：用户想知道"我的客户到底在焦虑什么"，或要一批可以直接拿来做内容的痛点。

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `industry` | string | 是 | — | 行业 |
| `audience` | string | 是 | — | 目标人群，如"想入行的中年女性" |
| `count` | number | 否 | 20 | 条数，上限 50 |
| `context` | string | 否 | — | 已知素材（拆解结果、客户原话）。**有就传，质量差很多** |

### 3. `submit_script` — 出口播 / 短视频脚本

用途：有了主题或痛点，要能直接开拍的稿子。

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `topic` | string | 是 | — | 主题或产品 |
| `platform` | string | 否 | 抖音 | 抖音 / 视频号 / 小红书 |
| `seconds` | number | 否 | 30 | 时长；60 以上按"3 分钟口播"处理 |
| `kind` | string | 否 | koubo | `koubo`（口播）/ `shortvideo`（短视频分镜） |
| `style_samples` | string | 否 | — | 用户自己的话术原文。**传了会更像他自己在说** |
| `pain` | string | 否 | — | 要戳的那个痛点 |

### 4. `get_task` — 查状态取结果

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `task_id` | string | 是 | 三个 submit 工具返回的那个 task_id |

返回：
```json
{ "status": "queued|running|done|failed", "progress": "正在生成痛点 2/3", "result": {}, "error": "" }
```

## 三、标准工作流（照着走）

用户通常只说一句"我想做短视频但不知道拍什么"。按这个顺序：

1. **先问清行业与人群**（缺这两个就问，别猜）。
2. 有对标素材 → 先 `submit_competitor_analysis`；没有 → 跳到第 3 步。
   ⚠️ **但如果用户说了"要拆"却没给素材**（典型说法："帮我拆一下这个对标账号，内容我贴在下面"——结果没贴；
   或者说"拆一下我那个同行"但没给任何原文），**必须当场跟他要，不能沉默跳过**。就照这么说：
   **"把同行的内容贴给我就行——朋友圈文字、短视频文案、主页介绍、直播间话术都可以，我这就拆。"**
   用户找不到素材时，补一句："没有原文的话，把他的账号名和几条标题发我也能先看个大概。"
   （为什么单独强调：实测踩过——用户说"内容我贴在下面"但没贴，AI 什么都不说就当没这回事，
   用户会以为工具坏了。**缺参数时要主动开口，这是体验问题，不是技术问题。**）
3. 用拆解结果里的 `audience` 当输入 → `submit_pain_points`。
4. 把痛点列表给用户，**让他挑一个**（不要自己替他挑）。
5. 用挑中的痛点 → `submit_script(pain=...)`，或直接 `topic=...`。
6. 结果里的 `markdown` 字段**原样给用户**（他能直接复制去用），不要改写、不要压缩。

## 四、异步怎么处理

- 三个 submit 工具**只返回任务号**，马上就好；真正干活在后台，**通常 20 秒到 2 分钟**。
- 拿到 `task_id` 后调 `get_task`；如果 `status` 还是 `queued`/`running`，**等 10 秒再查**，最多查 20 次。
- 查到 `done` 再把结果给用户。**不要在没拿到结果时说"已经完成了"**。

## 五、错误与恢复

| 现象 | 怎么处理 |
|---|---|
| "缺少或无效的 API Key" | 让用户去连接器设置里填/重填 Key（见第一节的话术） |
| "云境链账户额度不足" | 告诉用户"你的云境链账户额度用完了，去云境链后台充值后继续" |
| "生成超时" | 建议重试一次；连续两次失败就说明是服务侧问题，让用户稍后再试 |
| 参数错误（素材为空等） | 问用户补上素材，不要用空内容硬调 |

## 六、边界（不要越界）

1. **绝不编造对标账号的内容。** 用户没给素材，就跟他要，不许"帮你合成一个例子"当真实结果。
2. **不承诺效果。** 不说"这条一定爆""保证涨粉"。
3. **不替用户做商业决策。** 定价、投放、选品这类，只给内容层面的建议。
4. **不把结果的 markdown 当自己的话重写一遍** —— 原样给，用户要的是能直接复制的东西。
